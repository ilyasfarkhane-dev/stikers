# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Project layout — only two source folders at the root (the user wants exactly `frontend/` + `backend/`; do not add new top-level folders): `frontend/` (Vite root + `vite.config.mjs`: `index.html`, `public/`, `src/`) and `backend/` (`api.js`, `auth.js`, `db.js`, `local-bindings.mjs`, `mysql-adapter.mjs`, `node-env.mjs`, `node-http.mjs`, `server.mjs`, `shared/` catalog + defaults also imported by the frontend, `worker/index.js` thin Sites entry, `scripts/prepare-sites-build.mjs`, `tests/`, local dev data in `.data/`). Dependencies are split (user decision): `frontend/package.json` (react, react-dom, react-icons, vite, @vitejs/plugin-react) and `backend/package.json` (mysql2, vite for bundling the worker) each have their own `node_modules` + lockfile; there is no root `node_modules`. The root `package.json` has no dependencies — only delegating scripts (`npm install` runs both installs via `postinstall`; `dev`/`build`/`preview` → frontend, `start`/`test:*` → backend, `build` = frontend build + `backend` `build:sites`). Never add dependencies at the root. Build app UI in `frontend/src/`. Keep `backend/.openai/hosting.json` (copied to `dist/.openai/hosting.json` by the build), `backend/worker/index.js`, `backend/scripts/prepare-sites-build.mjs`, and `backend/tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Durable design decisions

- Brand is **Stick'Arts / Comstore**. Navbar logo: `frontend/public/assets/logo-black.png`. Footer logo: `frontend/public/assets/logo-white.png`.
- Visual system from the Stick'Art mock: white paper, charcoal `#1c1c1c`, gold accent `#c9a227`. Display/body: Outfit; script accent: Great Vibes (hero “créativité”).
- Hero left copy matches the Stick'Art detail mock: gold kicker with a short rule to its right, white headline with gold italic “créativité.”, two body paragraphs, gold primary + ghost secondary CTAs, then a compact trust row directly under the buttons (content-width only, not full-bleed). Right aside uses Caveat marker script, left-aligned, white, rotated ~-11°, with soft shadow (“Votre design / format / finition”).
- Navbar **Nos solutions** opens the dedicated `/solutions` page (not an in-page scroll). Home still includes the solutions section.
- `/solutions` page layout: dark printer hero (“Des stickers pour chaque besoin”) + trust strip → “Nos solutions par usage” 8-card grid → UV vs Éco-solvant tech compare → finitions rail + CTA → configurator steps bar.
- Navbar **Matières & Finitions** opens `/matieres-finitions` with the same visual system as `/solutions` (photo hero, trust strip, image cards, finitions rail + CTA, configurator bar). Content: 6 matières + 8 finitions.
- Navbar **Applications** opens `/applications` (and **Comment ça marche ?** opens `/applications#comment-ca-marche`), reusing the `/solutions` visual system: photo hero, trust strip, 10 sector cards, then a 6-step process bar. Content source: `projet_site_stickers.pdf` (sections 13–14).
- Navbar **À propos** opens `/a-propos` (`frontend/src/pages/AboutPage.jsx`) and **Contact** opens `/contact` (`frontend/src/pages/ContactPage.jsx`); the footer "Nous contacter" button also links to `/contact`. Both reuse the `/solutions` system (photo hero + `sol-trust` strip, `usage-card`, `sol-config` steps bar) plus `ab-*` / `ct-*` classes in `shop.css`. À propos (brief §6 "entreprise, atelier, équipements, savoir-faire"): hero "Stick'Arts, l'atelier stickers de Comstore" → trust strip → "Qui sommes-nous ?" story (overlapping photos + Roland & Mimaki badge) → "Notre atelier & nos équipements" 3 cards → dark "Ce qui nous guide" values + quote → process steps bar. Contact: hero "Parlons de votre projet", then overlapping charcoal "Nos coordonnées" card (téléphone, WhatsApp, e-mail, atelier, horaires — all from admin `site.topbar` / `site.contact`, hidden when empty) + white message form (nom, téléphone, e-mail, sujet, message, honeypot) → 3 quick-route cards. The form posts kind `message` (no items, message required) to `/api/public/requests`; messages appear in `/admin/demandes` with a charcoal "Message" badge and a "Messages" filter.
- E-commerce mocks (fiche produit, configurateur, formulaire, logique, matrice) are used for **structure only** — always render them in the existing site visual system (white cards, charcoal, gold, Outfit), never the mocks' navy styling.
- `/produit/:slug` product page (data-driven from the admin-managed `products` section), `/configurateur` (same layout as the fiche produit: hero → preview + 6 type thumbnails + assurances on the left, one card with 8 numbered fields + dark buy bar on the right → Matières × Finitions matrix as a static guide, independent of the current configuration (user decision: no greyed rows, no selected highlight, not clickable — same as on `/matieres-finitions`) → "Demander un devis" form card (`#devis`, opened by `?etape=coordonnees`) → "Comment est calculé votre prix ?" 9 info cards + price-rule tags), and a Matières × Finitions matrix on `/matieres-finitions` between finitions and the help bar. The configurator and product page share `COMPATIBILITY` (incompatible finishes disabled).
- Shop page design (`frontend/src/shop.css`, all `shop-* / pd-* / cfg-* / mf-*` classes): compact dark printer-photo hero (`ShopHero`: breadcrumb, gold kicker with rule, white headline with gold italic word, glass trust chips, optional Caveat aside), white content cards overlapping the hero bottom, numbered charcoal/gold field badges, pill chips with the site's `finish-swatch` swatches, charcoal buy bar / recap panel with gold glow, dark matrix section with gold check badges. Keep `styles.css` untouched for these pages.
- Configurator rules chain Type → Matière → Finition: each catalog type lists its allowed `materials` (first = default); `normalizeConfig` (`backend/shared/catalog.js`, used by both the site and the worker) switches material/finish automatically, and disallowed materials are greyed out in the matière chips only (the matrix always shows every matière).
- Prices: pricing coefficients default to `null` until real costs are entered in the admin (Tarifs), so the UI shows "— MAD" / "Estimation à calculer". Never invent tariffs. Estimates are computed server-side (`/api/public/estimate`); coefficients are never sent to visitors. Prices show on the site as soon as `pricingReady()` (impression/m² + marge + at least one matière) — each config still needs its own matière/finition/découpe coefficient, otherwise it shows "À calculer". The cart drawer shows a per-item price + "Total estimé" via `useEstimates`. Empty cart drawer (`cart-empty-*` in `shop.css`): white hero card with 3 overlapping round sticker photos + charcoal bag badge "0", title, copy and full-width gold "Configurer mon sticker"; then "Ou partez d'un modèle" rows (first 3 products: photo, name, subtitle, gold arrow → `/produit/<slug>`); charcoal trust strip pinned at the bottom (contrôle de fichier, livraison partout au Maroc, retrait atelier ou livraison).

## Backend & admin

- Content is editable from `/admin` (lazy chunk, no site header/footer, `frontend/src/admin/admin.css`, charcoal sidebar + gold accents). Sections: Tableau de bord, Demandes & commandes, Configurateur (types, matières, finitions, matrice, découpes, usages, quantités/formats/fichiers), Tarifs (+ simulateur), Produits, Contenu du site (hero, cartes Nos solutions, bandeau/contact, pied de page).
- Single source of defaults: `backend/shared/defaults.js` (site, catalog, pricing, products). The site reads `/api/public/site` via `SiteDataProvider` and falls back to these defaults if the API is unavailable.
- Backend API lives in `backend/api.js` (+ `db.js`, `auth.js`); `backend/worker/index.js` routes `/api/*` to it only when the D1 binding `DB` exists, otherwise falls back to assets. `backend/scripts/prepare-sites-build.mjs` bundles the worker into `dist/server/index.js`.
- Sites bindings: D1 `DB` (settings, requests, files metadata, login attempts; schema auto-created) and R2 `FILES` (customer artwork). Secrets: `ADMIN_PASSWORD` (≥ 8 chars, required) and optional `SESSION_SECRET` — set in the Sites panel, never committed. Locally they come from `backend/.env` (see `backend/.env.example`); dev uses `backend/local-bindings.mjs` (node:sqlite + filesystem); paths come from `DB_PATH` / `FILES_DIR` in `backend/.env` (default `backend/.data/dev.sqlite` and `backend/.data/files`).
- Database choice (user decision): **MySQL** locally (XAMPP MariaDB, port **3307** on this machine, started by the user from the XAMPP Control Panel) and on the user's own server; Sites hosting keeps using D1. `DB_CLIENT=mysql|sqlite` + `MYSQL_HOST/PORT/USER/PASSWORD/DATABASE` in `backend/.env`; `backend/node-env.mjs` builds the env for both the Vite dev middleware and `backend/server.mjs` (`npm start`, serves `dist/client` + `/api` on `PORT`). `backend/mysql-adapter.mjs` exposes the same D1 interface (`prepare/bind/all/first/run/batch`) over `mysql2`, auto-creates the database (utf8mb4) and returns a 503 JSON error when MySQL is down. `db.js` has separate SQLite/MySQL schemas and `upsertSql` (backtick the `key` column). Never import `mysql2` from `api.js`/`db.js`/`auth.js` (the Sites worker bundle must stay driver-free). `npm run test:api` runs the shared suite on SQLite and on MySQL (`<MYSQL_DATABASE>_test`, skipped when MySQL is unreachable).
- Checkout (user decision): the cart's "Finaliser ma commande" opens `/commande` (`frontend/src/shop/CheckoutPage.jsx`, `co-*` classes in `shop.css`): coordonnées → adresse de livraison → moyen de paiement, plus a dark sticky récapitulatif with per-item price + total. Payment methods = **paiement à la livraison** + **carte bancaire** (shown "Bientôt disponible" until a CMI merchant account is connected — never fake an online payment). Methods/labels/description/enabled/available + confirmation note are admin-editable in `site.payment` (Contenu du site → Paiement). The API validates the method server-side and stores `{payment, paymentLabel, city, address}` in the `requests.checkout` column (auto-added to existing DBs by `addMissingColumns`). The configurator `#devis` form is quote-only (kind `devis`).
- `/admin` dashboard design (`db-*` classes in `admin.css`): dark hero (date kicker, greeting with gold italic word, pending count, gold "Traiter les demandes" + ghost "Voir le site", glass "Montant en cours" panel), 4 clickable counters, then two columns — left: 14-day bar chart (gridlines, today highlighted) + Dernières demandes rows; right: status donut with clickable legend, "Configuration de la boutique" checklist (tarifs via `pricingReady`, carte bancaire, stockage fichiers, produits), top stickers ranking, 4 shortcut tiles.
- `/admin/configurateur` design (`cf-*` classes in `admin.css`): sticky dark "Parcours client" step nav on the left (icon, label, step hint, count; horizontal scroller under 1080px) + white section header (gold step kicker, title, text, dark "Ajouter" button). Types = horizontal cards (photo with dark gradient, order badge, floating move/delete tools, icon + name caption | fields, icon picker buttons, material chips with photo swatches and a "Par défaut" badge on the first). Matières / Finitions = swatch cards with a photo-swatch picker grid and compatibility counts. Matrix = click-to-cycle cells (charcoal/gold ✓ → yellow "?" + condition input → grey —) with row/column hover highlight and a combinations counter. Découpes & usages = compact rows with a star "Par défaut" button (sets `defaults.cut` / `defaults.usage`). Rules = Formats card (4 fields + format preview) on top, then Quantités (tier preview chips) + Fichiers clients (extension chips).
- `/admin/demandes` design (`rq-*` classes in `admin.css`): 4 counters at the top (from `/api/admin/stats`, "À traiter" in dark/gold), a toolbar card with search + Tout/Devis/Commandes segment + status chips with counts, then a list of clickable rows (ref + Commande gold / Devis outline badge, avatar + client, articles, amount + payment method, status, relative date). The detail drawer has a dark header (ref, status, big amount, Appeler / WhatsApp / E-mail), grey body with white cards (Client, Livraison & paiement tiles, Articles spec pills + file, Traitement clickable status chips, Historique vertical timeline) and a sticky Supprimer / Enregistrer footer.
- Requests from the configurator `#devis` form: kind `devis` (current config) or `commande` (cart items), with files `file_<index>`; refs look like `STK-YYMMDD-XXXX`. Run `npm run test:api` after backend changes.
- Product videos (user decision, overrides the earlier "no videos"): never show all videos on one page — each finish has its own product page with only its 2 photos (`gallery`) + 2 videos: `sticker-classique` (UV vernis), `sticker-eco-solvant`, `sticker-transparent`, `sticker-argente`, `sticker-dore`, `sticker-hologramme` (all in `DEFAULT_PRODUCTS`, info blocks via `productInfo`). Video thumbs sit in the same `pd-thumbs` row as the photos (dark tile, play badge, "Vidéo" pill); clicking plays the clip muted/looping in the preview stage (dark stage, portrait frame). The configurator (`/configurateur`) never lists all videos at once: an "En vidéo : <matière>" row (4 columns, finish label pill) under the type thumbs shows only the videos whose `material` matches the selected matière (vinyle blanc → UV vernis + éco-solvant, transparent → transparent, premium → argenté + doré, holographique → hologramme, film technique → no row), playing in the same preview stage. Every product page ends with "Découvrez nos autres stickers" cards linking the other product pages. Solution cards link: UV → sticker-classique, Éco-solvant → sticker-eco-solvant, transparents → sticker-transparent, premium → sticker-hologramme. Web copies live in `frontend/public/assets/videos/<id>.mp4` + `<id>.jpg` poster (720px wide H.264, no audio, ≤15 s, ~0.4–1.8 MB each), listed as defaults in `DEFAULT_VIDEOS` (`backend/shared/defaults.js`). Videos are admin-controlled (user decision): the library lives in `site.videos` (`{id, label, material, src, poster, visible}`; `src`/`poster` = path under `/assets/` or an uploaded `/api/public/media/<name>` URL, resolved with `mediaUrl`) and the site reads only visible ones via `useVideos()`. Videos are managed per product inside `/admin/produits` (user decision — no separate Vidéos page; `/admin/videos` just opens Produits): each product card has a "Vidéos de la fiche" block (`ProductVideos.jsx`, `pv-*` / `vd-*` classes) with "Importer une vidéo" (upload → new library entry assigned to that product, matière = product's first matière; no "existing video" picker — user removed it), and video tiles (preview, titre, matière configurateur, Visible toggle, Remplacer / Aperçu uploads, ←/→ reorder, × remove — deletes the video from the library when no other product uses it), plus an empty state. The Produits savebar saves `products` + `site.videos` together; "Valeurs par défaut" restores both. Uploads go to `POST /api/admin/media` (R2 `FILES`, key `media/<name>`, MP4/WebM ≤ 60 MB, JPG/PNG/WebP ≤ 8 MB) and are streamed publicly with HTTP Range support. A product with a missing or empty `videos` list shows no video section. Never link the raw originals; the `drop-source-media` plugin in `frontend/vite.config.mjs` removes `assets/images/imges/` from `dist/client`.
- Site photos (user decision): all content images come from the client's own Comstore sticker photos. Originals (4000px JPGs + raw MP4s with spaces/accents in names) live in `frontend/public/assets/images/imges/`; the site uses 1600px web copies in `frontend/public/assets/images/photos/` (`uv-vernis`, `eco-solvant`, `transparent`, `argente`, `dore`, `hologramme` `-1/-2.jpg`), listed in `SITE_IMAGES`. Product cards use `fit: "cover"`. The user rejected the gradient/color swatches: every `finish-swatch--<tone>` (chips, matrix, finitions rails, admin) shows a round crop of a real sticker photo from `photos/swatches/<tone>.jpg` (white=eco-solvant-2, clear=transparent-1, metal=dore-2, holo=hologramme-1, gloss=eco-solvant-1, matte=transparent-2, varnish=uv-vernis-2, lam-gloss=argente-2, lam-matte=argente-1). Logos and the palm prefooter texture are unchanged.
- Site copy follows the `projet_site_stickers.pdf` brief: French product names, "Commander" CTAs, and no claims (durability, payment, dpi) beyond what the brief validates.
- Page sections follow: Nos solutions → Nos finitions → Quel sticker / configurateur → Une technologie professionnelle → prefooter + footer.
- Nos solutions uses 7 product cards: 4 on the first row, then 3 centered on the second row. Card design: rounded white cards, optional black/yellow badge, product image, yellow stars, and a yellow 3D “Shop now” button with hard offset shadow.
- Nos finitions (compact strip, per the user's mock): left column = heading with thin gold vertical accent + subtitle, then directly below a row of 9 white finish cards (large round photo swatch filling the card width, regular-weight label). Right column = dark CTA card spanning the full section height (gold sticker photo `photos/dore-2.jpg` under a dark bottom gradient, left-aligned bold white copy, outline "Voir toutes les finitions" button → `/matieres-finitions`). The card rail slides ~2.75rem under the CTA card (rail above it, last card with a stronger shadow) and the CTA copy is indented to clear the overlap.
- Quel sticker: two white cards on light gray — left picker card (title + 7 need tiles in one row), right configurator card (image + copy + gold CTA).
- Une technologie professionnelle: slim 50/50 banner — left printer photo with dark Roland | Mimaki overlay, right copy with gold accent bar, body text, and 3 horizontal feature items with circular outline icons.
- Footer: palm-leaf prefooter with 3 columns + gold outline icons + ghost CTA; black bar with logo, pipe-separated nav, social icons; dark legal row with copyright + Mentions / CGV / Politique.
